Autopay Recovery Voice Agent - Solution Description

PROJECT OVERVIEW
Built an automated voice agent system for recovering failed autopay payments using Twilio voice 
integration. The system uses Interactive Voice Response (IVR) to guide customers through payment 
recovery options via phone calls.

TOOLS AND TECHNOLOGIES USED

Voice/Communication:
- Twilio (TwiML) - Voice provider for phone calls and IVR flows
- Twilio Node.js SDK - API integration for call management

Backend:
- Node.js (v14+) - Runtime environment
- Express.js - Web server framework
- dotenv - Environment variable management

Frontend:
- HTML/CSS/JavaScript - Web dashboard UI (no framework dependencies)

Data:
- JSON file (customers.json) - 10 fictional customer records with payment failure data
- In-memory storage - Call logs stored in memory for demonstration

Development Tools:
- Git - Version control
- GitHub - Repository hosting

DATA USED

Fictional Customer Records (10 records):
- Customer ID, name, phone number (placeholder values)
- Payment amount ($45.75 - $320.50)
- Due date, failed reason, payment method, attempt count
- Diverse failure scenarios: insufficient funds, card expired, bank declined, no payment method

Data Structure Example:
{
  "id": "CUST001",
  "name": "John Smith",
  "phone": "+15550000001",
  "amount": 125.50,
  "dueDate": "2026-10-01",
  "failedReason": "Insufficient funds",
  "paymentMethod": "Visa ending in 4242",
  "attempts": 1
}

Note: Phone numbers are fictional placeholders (+15550000001 to +15550000010) to ensure
no real calls are made without explicit user configuration.

GUARDRAILS AND HUMAN REVIEW

1. Phone Number Validation:
   - All customer phone numbers are fictional placeholders
   - Users must explicitly replace with numbers they control
   - Documentation explicitly states: "Use only a number you control or have explicit permission to call"

2. Credential Security:
   - .env file is in .gitignore and never committed
   - .env.example contains only placeholder values
   - No real API keys, passwords, or credentials in the repository
   - Environment variables used for all sensitive data

3. Permission Gates:
   - System requires explicit Twilio credentials to make actual calls
   - Demo mode available for testing without any external services
   - ngrok/public URL required for Twilio webhooks (prevents accidental calls)

4. Call Control:
   - Calls initiated manually via dashboard UI (not automated batch calling)
   - Single call at a time (no bulk calling to prevent abuse)
   - User must click "Initiate Recovery Call" for each customer

5. Rate Limiting Prevention:
   - No automatic retry logic (prevents spam calling)
   - No scheduled calling (requires manual initiation)
   - Call logs visible to track activity

6. Documentation Warnings:
   - Multiple warnings about using only numbers you control
   - Clear statement that this is a demonstration (no real payment processing)
   - Compliance reminders in documentation

7. Configuration Validation:
   - Server checks if Twilio credentials are configured
   - Dashboard shows configuration status
   - Graceful error handling if credentials missing

8. Human-in-the-Loop Design:
   - Dashboard allows human review before initiating calls
   - Customer information displayed before call initiation
   - Call logs provide transparency and audit trail

HUMAN REVIEW POINTS

1. Pre-Call Review:
   - Dashboard displays all customer details before call initiation
   - Human operator verifies customer information
   - Manual button click required to initiate each call

2. Post-Call Monitoring:
   - Call logs track all initiated calls with timestamps
   - Call SID recorded for each call (Twilio reference)
   - Status tracking (queued, in-progress, completed, failed)

3. Error Handling:
   - Clear error messages displayed in dashboard
   - Server logs capture detailed error information
   - Graceful degradation if Twilio unavailable

4. Testing Safeguards:
   - Demo mode allows testing without making real calls
   - Simulated voice messages displayed in terminal
   - No Twilio credits required for demonstration
